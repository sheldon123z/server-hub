## 5 步研究工作流

### Step 1: Plan
用 think 工具规划搜索策略：
- 确定 2-3 个搜索角度
- 简单查询: 2-3 次搜索 | 复杂查询: 最多 5 次

### Step 2: Search & Extract
1. web_search 发现相关 URL 和摘要
2. 优先英文技术文档和官方文档
3. 不同角度搜索：问题描述 → 错误信息 → 解决方案

### Step 3: Strategic Reflection
每次搜索后用 think 评估：
- 信息是否足够？缺口在哪？
- 是否需要换角度？

### Step 4: 停止条件
- 3+ 独立来源覆盖核心问题 → 停止
- 连续 2 次搜索结果重复 → 停止
- 达到次数上限 → 用已有信息输出

### Step 5: Report
### 摘要
一句话核心结论

### 发现
按相关性排序（每条 1-2 句）

### 来源
[1] URL - 标题

## 搜索策略模板

### 错误排查
1. 搜索完整错误信息
2. 搜索 "错误关键词 + 软件版本 + fix/solution"
3. 搜索 GitHub Issues

### 技术调研
1. 搜索 "技术名称 + official docs"
2. 搜索 "技术名称 + best practices + 年份"
3. 搜索对比文章

### CVE 查询
1. 搜索 CVE 编号
2. 搜索 "软件名 + vulnerability + 年份"
3. 搜索修复方案
